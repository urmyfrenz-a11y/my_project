# 플레이스 닥터 — 네이버 플레이스 세팅 진단

네이버 플레이스 주소(URL)를 붙여넣으면 **공개 페이지에서 확인 가능한 필수 세팅
항목**을 점검하고, 부족한 항목에 대한 **권고안**을 표로 제시하는 웹앱입니다.

- 도메인(예정): **https://naverplace.vercel.app**
- 스택: Next.js 16 (App Router) · TypeScript · 커스텀 CSS
- 표 구성: `필수 항목` · `현재 상태` · `권고` · `비고`
  - 정보 있음 → **O** + 값 표시, 권고 비움, 비고에 확인 포인트
  - 정보 없음 → **X** + "미등록", 권고 열에 조치안, 비고에 확인 포인트
  - 예약/톡톡/SNS 등 **선택 연동**은 없어도 감점 아님(선택 표시 + 소프트 권고)
  - 방문자/블로그 **리뷰는 숫자만** 표시

## 왜 서버에서 Scrapingdog 를 경유하나

네이버 플레이스는 공개 API가 없고, **데이터센터 IP(Vercel)를 캡차로 차단**합니다.
순수 브라우저(클라이언트) 호출은 CORS로도 막힙니다. 그래서 서버 라우트가
**Scrapingdog(한국 residential IP + JS 렌더링)** 로 플레이스 홈을 실제 방문자처럼
렌더링한 뒤, 페이지 내장 상태(`__APOLLO_STATE__`)를 파싱합니다.
사용자는 **사이트만 방문**하면 되고, 크롬 확장 설치가 필요 없습니다.

## 업종별 메뉴 차이 반영

네이버 플레이스의 "메뉴 탭"은 업종마다 다릅니다. 진단의 '상품·품목' 항목은
업종에 맞춰 라벨이 바뀝니다.

| 업종군 | 품목 라벨 |
| --- | --- |
| 음식·카페·주점 | 메뉴 |
| 숙박(호텔·펜션·글램핑) | 객실 |
| 의료(병원·의원) | 진료·의료진 |
| 클래스·공방·투어 | 코스·패키지 |
| 학원·헬스·미용·주차 | 가격(이용권) |
| 그 외 | 메뉴·상품 |

## 진단 항목

공통 필수: 업체명 · 업종 · 대표사진 · 상세설명 · 상품(업종별) · 주소 · 전화번호
· 영업시간 · 편의시설 · 소식
선택 연동: 예약/주문 · 네이버 톡톡 · 홈페이지/SNS
리뷰(숫자만): 방문자 리뷰 수 · 블로그 리뷰 수

> 대표키워드·스마트콜·통계 등 **관리자(스마트플레이스 로그인) 전용 항목은 제외**
> — 공개 페이지에서 확인이 불가능하기 때문입니다.

## 환경변수

`.env.local`(로컬) 또는 Vercel 프로젝트 환경변수에 설정합니다.

```
SCRAPINGDOG_API_KEY=...   # https://www.scrapingdog.com/dashboard (무료 1,000건/월)
```

## 로컬 실행

```bash
npm install
npm run dev      # http://localhost:3000
```

## 배포 (Vercel)

- 새 Vercel 프로젝트 생성 → **Root Directory = `naver-place-checker`**
- 환경변수 `SCRAPINGDOG_API_KEY` 등록
- 도메인 `naverplace.vercel.app` 연결

## 파서 튜닝 메모

네이버 내부 스키마는 필드명이 수시로 바뀝니다. `lib/extract.ts` 의 `normalize()`
는 정확한 키 하나가 아니라 **별칭 목록을 깊이 탐색**하는 방어적 방식입니다.
실제 플레이스로 처음 돌려본 뒤 값이 안 잡히는 필드가 있으면, 진단 요청 body에
`{"debug":true}` 를 넣어 `debug` 로 반환되는 원본 키/정규화 결과를 보고 별칭을
보완하세요. (`app/api/diagnose/route.ts` 참고)
